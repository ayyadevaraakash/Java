|      Memory Management     |
+----------------------------+

RAM = stack + heap + metaspace(early name-permgen (permanent generation))

Stack:
- stores temporary variables in a method
- separate block for each method
- store primitive data type
- store references of the heap objects
- each thread has its own stack
- when stack is full it will give java.lang.StackOverflowError

Garbage Collection:
- free up the memory if no one is pointing to the object stored in the heap, garbage collector runs periodically according to JVM, we cannot run GC by ourselves but we can make a appeal by calling System.gc()
- If we have a weak reference to an object, then even though there is a reference, still GC will clean it in the next cycle and we get a NULL
- If we have a soft reference to an object, then GC will forcefully clean it IFF there is a severe memory shortage in the system

Weak Reference Syntax:
import java.lang.ref.WeakReference;
WeakReference<Employee> weakRef = new WeakReference<>(new Student());

Soft Reference Syntax:
import java.lang.ref.SoftReference;
SoftReference<Employee> softRef = new SoftReference<>(new Student());

Heap:
- String Pool is there inside this
- There is no order of allocation inside heap
- GC is used to delete the unreferenced objects in the heap

Heap = Young Generation + Old Generation
Young Generation = Eden + Survivor space
Survivor space = s0 + s1

- Whenever an object is created it is first stored in young generation, now it might happen some are unreferenced and some are referenced
- After a certain time GC will run, it will see whoever is unreferenced, it will delete those, now whoever is referenced will be moved to either s0 or s1 (Mark and Sweeep Algorithm)
- Next time again some new objects might be created and stored in young generation, again when GC will happen, same process will be followed, along with that whoever is stored in s0 will be moved to s1 and vice versa (alternate every time)
- Now when objects are moving between s0 and s1, it's age increase every time, once it reaches a threshold it is "promoted" means, it is moved to old generation area

Important - Whenever GC is run in young generation, it is called as Minor GC and whenever it is running in new generation it is called Major GC

Metaspace (Perm Gen / Method Area)
- It stores static variables (also called class variables)
- It stores class metadata
- Use native memory, does not use Java Heap Memory

Old Generation is also called "Tenured Generation"

-- When Metaspace was known by the name "Perm Gen", it was part of heap memory, so it was not expandable, but now after becoming Metaspace, it is a separate entity outside of heap which uses native memory so it is expandable as per requirements

+------------------------+
|      Types of GC       |
+------------------------+

1. Serial GC
- It uses a single thread to perform GC, when this happens, all application threads are paused, once GC is done, application resumes. This is also called Stop-The-World (STW)

2. Parallel GC
- It is same as Serial GC, but it uses multiple threads so work is completed faster and STW time is reduced

3. Concurrent Mark-Sweep GC
- It tries level best to work concurrently with the application threads, so it minimizes the STW time and in best case, it will not cause STW. Here defragmentation does not happen, so free space can be in fragments

4. G1 (garbage first) GC
- It is similar to concurrent mark sweep gc, but it defragments the free space as well. Also, it has some concurrent improvements, so it is the default GC algorithm since java 9.

Till Java 8 (inclusive) - Parallel
From Java 9 onwards - G1

How float is stored in Java?
It uses 32 bit IEEE 754 standard

sign bit - 1 bit
exponent - 8 bit
mantissa/significant - 23 bit

Convert float number to machine representation-
step 1 - convert the number to binary number
step 2 - convert to 1.___  x  2^(u)
step 3 - add bias to exponent (float bias is 127)
step 4 - write binary in form of sign bit, exponent and mantissa

remember that, 1.____, here ____ is called mantissa

To convert back in reverse fashion-
[(-1)^(sign bit)] x [(1 + mantissa)] x [2 ^ (exponent - 127)]

+------------------------------------+
|      Singleton Design Pattern      |
+------------------------------------+

We already know how to write normal singleton design pattern using eager initialization and lazy initialization.

In two phase locking, there is a problem, there may be multiple cores, we know that each core is having its own cache, so generally whatever variable you might be using to hold the object will also exist in the respective cache, now what if someone asks for the object in other cache, then it will again show NULL which will result in creation of an object once more. So, whatever static variable we have created for holding the object should be declared as "volatile". Marking it as volatile means it will not rely on cache, all read/write operations will happen directly on memory level.

Bill Pugh Solution of Singleton Design Pattern - There is another solution which is faster than two phase locking and also ensures thread safety.

class Singleton {

    private Singleton() {
        System.out.println("Object created");
    }

    private static class SingletonHelper {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return SingletonHelper.INSTANCE;
    }
}

In Java, inner classes are not loaded when outer classes are loaded at the start of the program, it is only loaded on demand when someone refers it. Also the initialization of a class in java is thread safe and the guarantee is given by JVM internal working itself.

There is another way of achieving this using ENUM, enum initialization is also thread safe guaranteed by JVM, constructor is automatically private.

enum Singleton {
    INSTANCE;
}

Why Map Interface has a separate hierarchy?
All collections in Iterable tree are based on data structures which stores values, and operations involved on those values and indices, but in map interface we are interested in storing the key, value pairs and operations which deal with K,V pairs

==> HASHMAP

Initially, there is a interface Map<K,V>, in this interface there is a nested interface Entry<K,V> which, if some class implements has to implement getKey(), getValue() etc methods

So Map<K,V> Interface has size(), isEmpty(), containsKey() etc
Entry<K,V> has getKey(), getValue() etc

Now HashMap<K,V> is one of the class which implements Map<K,V>, so hashmap has to provide implementation for size(), isEmpty() etc. Now, in hashmap, we have a nested static class Node<K,V> which implements the Map.Entry<K,V> interface so it has to provide the implementation of getKey(), getValue() etc

Also, in class HashMap<K,V> there is a entry Node<K,V>[] table, which create a array of Node

by the way, class Node looks like this,
class Node:
	final int hash;
	final K key;
	V value;
	Node<K,V> next;
	
We already know the implementation of hashmap, so I will only write some important things which should get special attention

Initial settings of hashmap,
DEFAULT_INITIAL_CAPACITY = 1 << 4; (2 power 4 is 16)
DEFAULT_LOAD_FACTOR = 0.75f
TREEIFY_THRESHOLD = 8;

Now, when size of hashmap reaches 0.75 (75%) of initial capacity, then the capacity increases to (2 power 5 = 32) and this process continues, Thus, we understood what is initial capacity and load factor

Now, we already know that at every array index we are maintaining a linked list, when this linked list size becomes greater than or equal to TREEIFY_THRESHOLD, then the linked list gets converted to balanced binary search tree (Red Black Tree)

Thread safe(HashMap) = ConcurrentHashMap or HashTable

==> LINKED HASH MAP

It is a kind of hash map, but it has two special features, it can maintain either
1. Insertion Order
2. Access Order (Acces the most recently used ones)

Internal implementation is same as hash map, but it uses doubly linked list, In class LinkedHashMap we have a nested class Entry<K,V> extends HashMap.Node<K,V>, so we have those 4 fields in hashmap plus before and after pointer, so, it means, whenever a new node is inserted, the value is stored in the after pointer, thus maintaining insertion order

Now, when initializing LinkedHashMap we can use the constructor LinkedHashMap(int initialCapacity, float loadFactor, boolean accessOrder), if we give accessOrder as true, we can have a "Access Order" LinkedHashMap

LinkedHashMap is not a thread safe collection and there is no thread-safe version available as well. To get a thread safe version of it, we will use the Collections utility class and create a object by this syntax,
Map<K,V> mp = Collections.synchronizedMap(new LinkedHashMap<>());

==> Tree Map

It is a sorted version of hashmap which maintains ascending order of keys when storing enteries, It internally uses Red Black Tree

SortedMap methods : heapMap(till which key), tailMap(from which key), firstKey(), lastKey()

NavigableMap methods : lowerEntry(key), lowerKey(key), floorEntry(key), floorKey(key), ceilingEntry(key), ceilingKey(key), higherEntry(key), higherKey(key), firstEntry(), lastEntry() etc

I personally thing that NavigableMap methods can be used to perform binary search on an array, it can replicate upper bound and lower bound methods
